# Flux-rs 是什么

写给用户看的介绍。技术设计在 `blueprint.md`，这里不谈实现。

> **当前状态：设计完成，功能尚未实现。** 下面描述的是这个东西被设计成什么样，不是你今天能装上用的东西。别的都可以往后放，这一句不能。

---

## 一句话

**你挑几个应用，只有它们的联网走代理，手机上其它一切照旧。**

---

## 它解决什么问题

手机上想让部分应用走代理，常见办法是装一个代理软件，它会建立一条 VPN 连接，然后把**整台手机**的流量收进去，再按规则决定哪些放出去、哪些绕过。

这个办法能用，但有三个代价：

**第一，占掉了系统唯一的 VPN 位置。** Android 同一时刻只允许一个 VPN。代理软件占着它，你公司的 VPN 就连不上了，反之亦然。

**第二，所有流量都得先绕一圈。** 即使某个应用最终是直连，它的数据也已经先进了代理软件、被判断了一次、再送回系统。这一圈是白走的。

**第三，你很难确认它到底在做什么。** 全局接管加规则匹配，出问题时"这个应用为什么走了/没走代理"往往说不清。

Flux 换了个位置做这件事：**不建立 VPN，不接管全局。** 它在系统内核里做一次判断——这个数据包属于哪个应用——只有你挑中的那几个才被送进代理，其余的连"被看一眼"都没有，走原本的路。

因此：

- **VPN 位置是空的。** 你的公司 VPN 照常用。
- **没挑中的应用完全不受影响。** 不是"被规则放行",而是从来没进来过。
- **能说清每个应用的去向。** 有一条命令直接告你某个应用现在走哪条路、为什么。

---

## 你会得到什么

### 只代理你选的应用

在一个文本文件里列出应用包名，保存，重新加载。就这样。

### 应用查域名也走代理

这一条容易被忽略，但它是最要紧的。

你的应用要连一个网站，得先问"这个网站的地址是多少"。这个询问动作在 Android 上不是应用自己做的，而是交给系统的解析服务代办。所以很多按应用分流的工具**只代理了后面的连接，没代理前面的询问**——结果是:你访问了哪些网站,运营商依然一清二楚,虽然内容它看不到。

Flux 能连这一步一起代理。原理上有个不容易发现的细节：Android 的系统解析服务在替应用查询时，会把那条连接的归属**改回发起查询的应用**。所以在内核看来，那就是这个应用自己的流量，可以被一起挑走。

**代价要说清**：如果你开了系统设置里的"私人 DNS"（加密 DNS），那部分查询本来就是加密的，Flux 不去动它。

### 它不骗你

设计里有一条硬规则：**宁可什么都不做，也不假装在工作。**

- 如果某个环节不满足条件，它会停在"未激活"并**说清是哪一项不满足**，不会装作在跑。
- 如果一切正常但某个网络（比如 Wi-Fi）上被手机厂商自己的功能占了位置，它会告诉你"蜂窝正常、Wi-Fi 不行、原因是这个"，而不是笼统地报错。
- **任何失败都不会让你断网。** 判断出错时的默认行为是"当作没挑中这个应用"，流量走原路。

### 有一条能真正回答问题的命令

```
$ fluxd explain com.example.app

应用            com.example.app
是否选中        是

当前接管路径
  Wi-Fi         未接管 —— 位置被手机厂商的流量统计功能占用了
                我们的程序装上了，但一个数据包也没收到
                （这一分钟里网卡发出 12043 个包，我们收到 0 个）
  蜂窝数据      已接管，正常工作

已知不会被接管的情况
  · 这个应用通过系统下载器下载的文件
  · 这个应用走 VPN 时的流量（现在没有 VPN）
  · 加密 DNS（你现在是机会加密模式，普通查询会被接管）

结论
  Wi-Fi 下不生效，蜂窝下生效。是手机厂商占位，不是你配置错了。
```

最后一句是重点：**它会区分"你配错了"和"这台手机就这样"。** 混在一起的话，你会反复改配置而永远改不好。

## 怎么用

### 需要什么

- 已 root 的 Android 手机（Magisk、KernelSU 或 APatch 三者之一）
- 内核版本 5.15 或更新
- arm64 处理器（近几年的手机基本都是）

装上之后，它会检查这台手机是否真的具备所需能力——**不是查版本号，而是实际去做一遍看能不能成**。做不到就明确告诉你哪一项做不到。

### 三个文件

装完之后你会有一个目录，里面是：

| 文件 | 干什么 |
|---|---|
| `flux.toml` | 你挑哪些应用。带注释，照着填 |
| `sing-box.json` | 代理本身的配置（服务器、规则）。首次会从模板生成 |
| `disable` | **开关**。这个文件存在就是关，删掉就是开，立即生效，不用重启 |

用一个文件当开关，是因为它足够简单：文件在就是关，不在就是开，重启之后语义不变，不需要另外记一份"上次是开还是关"。

### 代理部分交给成熟工具

Flux 只负责"挑出哪些应用的流量"。挑出来之后怎么走——用哪个服务器、按什么规则、延迟多少——由 [sing-box](https://github.com/SagerNet/sing-box) 负责，它是这个领域成熟的工具，Flux **原封不动**地用官方版本，不打补丁。

管理服务器和查看状态用 [zashboard](https://github.com/Zephyruso/zashboard)，一个网页控制面板。Flux 不自己做一个——那只会多一份要维护的东西和多一个安全面。

### 订阅

如果你有订阅链接，一条命令取回并配置好：自动识别格式、解析节点、按地区分好组、过滤掉机场塞在节点列表里的公告条目（"剩余流量"、"到期时间"、"官网地址"那些），然后校验、原子替换。

**校验不过就不替换。** 订阅更新不会把你的网络搞没。

## 要提前知道的几件事

诚实比好看重要，所以这些写在前面而不是藏在文档深处。

**一、系统流量统计会翻倍。** 被代理的流量在系统里被记两次——应用发出的那一次，和代理发出去的那一次。所以设置里的按应用流量数字会比实际用掉的多。Flux 不去篡改这个数字，因为篡改系统统计是更糟的事。

**二、"代发"的流量抓不到。** 如果应用把下载任务交给系统下载器，那份流量在系统看来属于下载器，不属于你的应用，因此不会被代理。DNS 是个例外（前面说过）。

**三、有些手机的 Wi-Fi 可能不行。** 我在一台三星手机上实测发现，厂商自己的流量统计功能占了 Flux 需要的那个位置，而系统规定那个位置只能有一个。这种情况下 Flux 会明确告诉你，而不是默默不工作。蜂窝数据不受影响。

**这类冲突无法预先知道**——每个手机厂商都往系统里加自己的东西，谁占了什么没有公开资料。所以设计上的对策不是"猜"，而是**装上之后实测一遍，确认自己真的收到了数据包**，收不到就报告并跳过那个网络。

**四、只按应用挑，不按网站挑。** "这个应用走代理"是 Flux 的事；"这个应用访问某个网站时走哪个服务器"是 sing-box 的事。别在 Flux 这边找按域名分流的开关。

**五、出问题怎么办。** 从轻到重四条路，任何一条都不需要电脑：

1. 建一个 `disable` 文件——立即停用。
2. 在 root 管理器里禁用模块，重启。
3. 卸载模块——它会清掉自己在系统里留下的所有东西。
4. Magisk 安全模式 / KernelSU 关闭全部模块——**必定恢复**。

第 4 条是最终保证。你应该在装之前就知道它存在。

## 它不做什么

| 不做 | 为什么 |
|---|---|
| 自己做代理控制面板 | sing-box + zashboard 已经成熟 |
| 自己实现代理协议 | 同上 |
| 按网站/域名分流 | 那是 sing-box 的职责 |
| 修改官方 sing-box | 用原版。改了就要为改动负责 |
| 自动检测断网并回滚 | 判断"网络是否正常"需要主动探测，离线时会误判——一个会误判的自动回滚，比没有更糟，它会在你正常用的时候把代理关掉 |
| 后台常驻通知 | 这是 root 模块，你是主动来找它的 |

---

## 名字

Flux 是"流"。这个项目做的事就是把流分开：一部分走这边，一部分走那边，互不干扰。

`-rs` 是 Rust——上一代 Flux 是 shell 脚本加 iptables 做的，这一代换成 Rust 加内核内的 eBPF 程序重写。
